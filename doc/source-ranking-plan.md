# 漫画源与书源质量评分及搜索调度方案

## 状态与目标

2026-11-15 整理并按用户授权实施本地 P0–P3，本地实现已通过交付验收。P4–P5 公共共享按用户选择保留为后续规划。初始权重和阈值已落地，后续结合真实使用数据校准。

目标包括以下四项。

- 搜索错误持续出现时自动降级，减少失败源占用搜索资源。
- 根据稳定性、速度和用户有效行为提升优质源的优先级。
- 缩短首个有效结果的等待时间，同时保留冷门作品的搜索机会。
- 在用户主动开启后共享汇总统计，让其他用户受益。

### 初始参数

- 服务端按源类型、身份及规则指纹保存最近 7 天、每操作最多 168 个小时桶，时间权重半衰期为 24 小时。规则更新后重置当前版本的观察记录。
- 可靠性采用成功与失败各 2 的中性先验，基础评分由可靠性 70% 和速度 30% 组成。搜索空结果计可用成功，有效命中比例限制速度奖励。
- 连续失败 3 次降级。连续失败至少 5 次且跨度至少 2 分钟时进入冷却。限流立即进入冷却，首次 1 分钟，退避上限 1 小时。
- 冷却期满后允许按需试搜，连续成功 2 次后结束恢复观察。累计衰减有效样本达到 5 且评分至少 75 时可进入优先状态。
- 30 秒内至少 3 个不同源发生网络错误或超时后，暂缓将后续同类错误计入长期评分。
- 每轮最多三路源搜索。同站点组内部依次执行，各组轮转，新源及恢复源保留一个靠前探索位置。站点依据源声明地址识别，漫画源缺少地址时使用独立源身份。
- 下载任务的最终结果与逐章、逐图调用分别统计，连续 3 个下载任务失败会降低搜索综合分。最近 128 个显式事件 ID 用于有界去重，普通调用在执行边界记录一次。
- 浏览器分别保留漫画与小说最近 30 天、最多 200 个源的兴趣记录，每源保留最近 128 个行为标记。兴趣衰减半衰期为 7 天，自动兴趣加分最高 8 分，手动优先加分为 10 分。
- 下载创建和完成按本次搜索中的作品归因，批量章节任务共享奖励标记。完成奖励仅关联当前浏览器创建过的任务，跟踪上限 200 个任务。

阈值集中在 [质量服务](../apps/server/src/services/sourceQuality.ts) 与 [浏览器兴趣记录](../apps/web/src/lib/sourceInterest.ts)。原有漫画 24 小时内存健康提示继续提供辅助证据，调度使用新增的持久化评分。

### 受控基线

使用三个各耗时 1000 ms 的空结果源和一个耗时 10 ms 的有效结果源，固定三路并发，通过可控时间执行实际搜索队列。

| 指标         | 原始顺序 | 质量排序 |
| ------------ | -------- | -------- |
| 首个有效结果 | 1010 ms  | 10 ms    |
| 源请求数     | 4        | 4        |
| 完成源数     | 4        | 4        |
| 有效作品数   | 1        | 1        |

基线对应 [受控回归](../apps/server/test/sourceQuality.test.ts)，用于验证排序机制及覆盖率。真实站点的耗时、限流和下载成功率需要后续使用积累。

## 质量模型

### 评分维度

| 维度     | 信号                                   | 规则                                           |
| -------- | -------------------------------------- | ---------------------------------------------- |
| 可用性   | 成功率、连续失败、错误类别、近期恢复   | 搜索、详情、目录、内容获取分别统计             |
| 速度     | 单源执行耗时、成功请求耗时分布         | 与排队耗时分开，区分空结果与非空结果           |
| 结果价值 | 详情打开、目录打开、下载发起、下载成功 | 点击弱加分，成功下载强加分，行为按机会数归一化 |
| 个人偏好 | 收藏、手动优先、持续选择               | 按实际用户或浏览器会话归属，归属能力需先核实   |
| 公共口碑 | 经聚合、满足样本量要求的公共统计       | 作为冷启动先验，由本地实测持续修正             |

本地首版可采用 `基础分 = 70% × 可靠性分 + 30% × 速度分`，各分项归一化到 0–100。低样本可靠性向中性先验收缩，速度参考固定基线并限制加分上限，避免快速返回空结果长期占据优先位置。有效行为积累后再加入结果价值权重。本地初始先验、速度映射和权重已落地，参数见前文，后续结合真实使用校准。

资格筛选、人工选择与冷却状态先决定可参与范围，评分决定范围内的次序。为不同操作保留分项，搜索排序主要使用搜索表现，并参考后续内容获取成功率。已知下载持续失败的源应展示对应原因并降低端到端质量评价。

### 统计口径与错误归因

- 正常空结果记可用性成功，命中率只作辅助信号，结合后续有效行为判断价值。
- 用户取消、队列中尚未启动的任务、未实现能力、无效输入分别记录处置原因，可用性分母排除这些事件。
- 超时、连接失败、解析失败分类统计。限流触发冷却和请求预算收缩，登录失效触发当前实例的处理提示。
- 同一时间大批源连接失败时识别实例网络异常，暂停据此作出长期质量降级。
- 单次操作在一个边界记录，重试与父级下载任务关联，避免章节数、重试次数和多层调用放大权重。
- 样本附带源类型、稳定本地身份、规则版本指纹、操作、耗时、错误类别和时间。规则变更后建立新版本样本，当前首版在版本变更时重新观察，历史版本退出当前评分。
- 使用有界滚动时间桶、近期衰减和最低样本量。持久化更新处理并发与重复事件，重启后恢复冷却截止时间与历史统计。

### 自动调度状态

建议状态为待观察、正常、优先、降级、暂时隔离。状态与人工启停分别存储。

- 新源进入待观察，获得少量探索机会。
- 足够有效样本支持稳定和快速时进入优先。
- 近期持续失败时降级，更长时间持续失败时进入暂时隔离。判断结合次数、时间跨度和错误类别。
- 隔离后采用退避冷却，期满进入恢复观察，限制同时探测数；探测绑定用户真实请求，首版按需执行。
- 恢复成功后逐步回升，使用不同的降级和恢复条件抑制状态反复切换。
- 用户手动停用的源始终排除。手动指定源允许显式试搜，仍遵守请求频率限制，并显示当前健康原因。
- 自动隔离保留源记录、订阅关系和配置，用户可以查看依据、重试或恢复默认策略。

当前失败次数、冷却时长及恢复样本量见初始参数，已通过可控时间和真实 Worker 回归。

## 搜索调度与交互

1. 根据人工启停、能力和订阅状态确定候选范围。
2. 对优先、正常、待观察及降级源排序，暂时隔离的源进入单独的跳过或探测路径。
3. 在既有有限并发队列中先启动优质源，为新源和恢复源保留少量探索名额，限制同站点并发，避免镜像源集中请求。
4. 继续逐源展示结果。采用有限候选快照和站点组轮转，依次执行其余候选。
5. 用户取消时保留已完成结果，停止后续启动，忽略迟到响应，取消操作排除出失败评分。

默认继续完成当前符合调度条件的搜索，优先改善首批有效结果速度。结果足够时自动结束搜索属于独立产品取舍，需确认后再实施。

用户已确认小说默认跳过冷却源并提供“包含隔离源重试”。流式协议通过候选数、安排执行数、跳过列表和完成数表达本次范围，网页同步处理全部源冷却的情况。

源管理页显示状态、分项证据、更新时间、冷却截止时间和人工选择。搜索页显示已完成、等待、跳过及失败摘要，用户可展开查看原因。

## 自愿共享的汇总统计

共享功能建议默认关闭，由部署管理员主动开启，并明确告知受影响用户采集范围。涉及个人行为的共享还需确认用户知情及退出方式。

- 上传白名单按源、规则版本、操作与时间桶聚合的计数、耗时直方图和错误类别。
- 关键词、作品名、作者、内容 URL、Cookie、Token、原始错误信息和原始行为事件留在本地。
- 共享身份需映射到经确认的公开源及其版本。私有源使用本地统计，只有经用户明确选择公开后才可进入公共目录。
- 单纯哈希私有 URL 无法保证匿名。设计上传协议时核查标识、维度组合、时间粒度及可关联风险。
- 公共评分达到最小独立实例数及样本量后发布，限制单实例贡献，处理重复上报、异常突增和批量伪造贡献。安装标识只作为贡献控制的一项信号。
- 接收服务定义日志 IP 保留策略、统计保留期、撤回边界、访问控制和运营归属。界面说明退出后停止上传，以及已聚合历史数据的处置方式。
- 公共数据附带更新时间、样本量及置信度，限制其排序影响。共享服务故障时继续使用本地评分和调度。

### 建议任务顺序

#### P0 观测与数据基础

1. 确认漫画、小说及订阅更新后的身份与版本映射，明确同源镜像的处理。
2. 定义操作事件和错误分类，复用现有漫画健康边界与小说执行结果，补充内容获取结果。
3. 设计持久化时间桶、容量与保留上限，处理幂等、并发、删除源后的清理及版本切换。
4. 记录基线并输出可检查的聚合结果，核实敏感字段未进入质量统计。

#### P1 本地评分与恢复

1. 实现样本置信度、时间衰减和分项评分，确定初始阈值。
2. 实现降级、冷却、恢复观察和人工重试，冷却状态持久化。
3. 在源管理页复用健康展示，增加原因、冷却与恢复操作。

#### P2 搜索调度

1. 漫画网页、漫画服务端聚合及小说执行队列接入统一评分决策，各自沿用原有执行方式。
2. 接入优先顺序、探索预算、等待上限和站点请求预算。
3. 同步已确认的小说隔离行为、OpenAPI、生成类型、服务端与网页统计语义。
4. 验证冷门结果、空结果、慢源、全源失败、大量源与取消路径。

#### P3 个人兴趣

1. 确认用户、浏览器与部署实例的归属边界，以及兴趣数据保留方式。
2. 关联搜索、详情、目录和下载，按操作去重、限制贡献，降低单纯点击带来的排序偏差。
3. 评估头部源曝光集中程度，调整探索和个人加权上限，提供重置入口。

#### P4–P5 公共共享

1. 确认公共服务运营、公开源目录、用户告知和数据处置方式。
2. 先完成本地汇总预览、上传白名单与公共聚合验证。
3. 验证匿名性边界、伪造与重复贡献、接收端日志及故障降级。
4. 最后接入带置信度、时效及影响上限的公共排序先验。

## 验证与效果衡量

- 业务回归覆盖空结果、取消、限流、登录失效、解析失败、网络集体异常、规则更新、重启、并发与重复事件。
- 状态机测试采用可控时间，覆盖阈值边界、冷却与恢复，避免依赖真实等待。
- 调度测试使用固定快慢源和故障夹具，对比相同候选集、并发和网络条件下的首个非空结果耗时、前若干有效结果耗时、搜索完成耗时、请求数及结果覆盖率。
- 记录 P50/P95、超时与限流比例、下载成功率、新源探索覆盖和恢复耗时。首批速度提升同时检查结果覆盖及请求负载。
- 真实站点验证保留网络环境、规则版本与样本量，结合下载可用性复核排序。
- 网页验证覆盖桌面和移动端的状态解释、人工重试、跳过统计、取消及迟到结果处理。
- 涉及协议修改时以 OpenAPI YAML 为源同步生成类型，运行受影响业务测试与契约检查。

数值性能目标在 P0 建立可复现基线后确定，每阶段以对应验收结果决定是否推进。
