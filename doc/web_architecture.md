# apps/web 前端架构

## 定位与结构

React/Vite 客户端提供源管理、搜索、详情和章节预览、下载管理，以及可选的管理员登录。章节图片用于预览，本次不扩展阅读器能力。

- `src/main.tsx`：挂载 App 和加载样式。
- `src/App.tsx`：AuthGate 包裹业务 Workspace，协调页面状态与 SSE。
- `src/app/AppShell.tsx`：页面布局、全局错误及连接提示；tab 状态和 hash 同步由 `App.tsx` 管理。
- `src/app/LoadingStatus.tsx`：加载图标与可被辅助技术读取的状态文案。
- `src/app/AsyncImage.tsx`：图片加载、失败、重试及完成后的淡入反馈。
- `src/lib/downloadSnapshot.ts`：每个 Workspace 独立的下载快照存储；`LiveDownloadsView` 订阅完整列表，`AppShell` 订阅活动任务数。
- `src/features/*`：搜索、源、下载及鉴权界面。
- `src/hooks/*`：各业务功能状态与异步操作。
- `src/api/client.ts`：同源 HTTP 请求、CSRF 请求头和结构化错误。
- `src/api/auth.ts`：鉴权 API，类型来自 OpenAPI YAML 生成产物。
- `src/api/venera.ts`：业务请求封装与资源 URL。
- `src/types.ts`：尚未迁移到生成契约的业务类型及 UI 类型。
- `src/styles/*`：基础、布局、组件和页面样式。

当前使用 hash tab，无额外路由库或全局状态库。首次加载读取地址中的 tab；应用内导航同时更新状态和 hash，`hashchange` 监听器负责浏览器前进、后退及外部 hash 变化。不要用依赖 activeTab 的 effect 持续回写 hash，避免覆盖浏览器历史导航。新增页面先沿现有功能边界拆分，不将业务逻辑堆回 App。

## 登录与会话

AuthGate 先请求 `/auth/session`，请求期间显示连接动画并禁用重复重试，失败后恢复重试入口；登录提交也显示忙碌状态。none 模式直接挂载业务 Workspace；required 模式只有登录成功后才挂载，避免未登录时启动业务请求和 SSE。

Cookie 由服务端设置，浏览器 JavaScript 不读取会话 ID。CSRF Token 存在内存中，每次启动从会话接口取得；HTTP client 为写操作自动附加它。不要将 Session 或 API Token 保存到 localStorage，也不要拼到 URL。

业务请求返回 401 时通知 AuthGate 重新检查登录状态；SSE 的 auth-expired 事件同样触发该流程。Workspace 卸载时关闭 EventSource。网络断开时通过会话检查和 EventSource 原生重连恢复，不把所有网络错误当作密码错误。

账号设置提供改密和退出；TokenPanel 创建、查看元数据和撤销外部客户端 Token。新 Token 仅保存在当前组件内存并展示一次，关闭或卸载后不再显示。

## API 与部署边界

所有 API 方法通过 client 封装。路径参数使用 encodeURIComponent，查询参数使用 URLSearchParams。图片、CBZ 和 SSE 使用同源资源 URL，Cookie 自动随请求发送。

浏览器固定使用 `/api/v1`。开发由 Vite 代理，独立部署由站点入口反向代理至 Server；当前不支持浏览器直接跨站 Cookie 登录。

协议源是 `packages/contracts/openapi.yaml`，生成文件禁止手改。现阶段鉴权接口使用生成类型和服务端 schema；已有业务接口保留原有类型与封装，后续按功能迁移。

## 搜索与详情状态

`useSearch` 区分正在编辑的搜索条件与已提交的 `searchQuery`；后者不表示请求已成功。提交时去除关键词两端空白，空关键词不发请求；聚合搜索还要求至少选择一个源。

- 分页继续使用已提交的关键词、源和返回的 cursor/page；编辑输入框或切换源不能改变已有结果的查询归属。
- 结果区展示已提交的关键词和搜索方式；漫画卡片使用结果所属源打开详情。仅编辑搜索控件时保留已有结果；提交新搜索后立即切换查询上下文，清空旧结果和分页信息，并显示等待状态。
- 搜索错误通过 `searchError` 在结果区展示，与成功但无结果、主动停止分别提示。加载更多失败时保留已有结果和分页游标，可再次加载；开始下一次搜索或加载更多时清除错误及停止提示。已取消或过期请求的错误不覆盖当前状态。
- 点击漫画后立即打开详情弹窗，显示漫画标题和加载状态；失败保留弹窗并提供重试。
- 详情请求通过递增序号校验。关闭弹窗或请求另一本漫画后，旧响应不能重新打开或覆盖当前详情；这只丢弃旧结果，不中止已发送的插件调用。
- 聚合搜索通过现有单源接口分批返回，最多同时请求 3 个源，为详情、图片与 SSE 保留浏览器连接。单个源失败不清除其他源结果；未完成源显示进度。
- 停止搜索会中止浏览器请求、停止派发排队的源，并保留已完成结果；旧响应不能覆盖当前搜索。中止 HTTP 不保证已发往插件的调用同时停止。快速源的漫画可在其他源仍搜索时打开，详情内操作使用独立忙碌状态。
- 打开详情不自动加载章节图片。章节预览和页数统计由用户触发；预览最多显示前 8 页缩略图。章节按每页 100 章渲染，可直接选择页码。
- 章节支持按名称筛选，忽略大小写及关键词首尾空白，先筛选再分页；修改或清除筛选回到第一页。筛选显示匹配数量及筛选外已选章节数量，无匹配时提供提示和清除入口。跨页、跨筛选保留勾选，筛选不改变下载所选章节的范围；全选/清空/反选始终作用于全部章节，筛选期间按钮明确标注“全选全部章节”和“反选全部章节”。切换漫画会重置筛选、页码及勾选；无章节时不显示筛选和章节选择控件。

## 等待反馈与图片状态

初始加载与全局刷新显示源、下载和缓存的加载状态；源列表仍未返回时不提前显示“暂无漫画源”。当前源设置、保存/Cookie 等操作和源设置 callback 在各自区域提供加载反馈，避免仅禁用按钮而没有原因。

详情内章节列表请求、页数统计和批量创建下载显示具体操作。进度区域位于禁用的 fieldset 之外，并在弹窗内保持可见，因此统计期间仍可点击停止；统计进度来自实际已处理章节，失败章保留为未统计，后续统计只重试缺失部分。关闭详情会中止浏览器侧预览/统计请求，忽略旧响应，不再派发剩余章节；不承诺同步取消插件内已开始的调用。已提交的下载创建继续完成，但关闭详情后不会被旧创建操作强制切换页面。

章节请求失败在详情弹窗内显示错误及重试入口，返回空图片列表也显示明确提示。`AsyncImage` 预留图片比例、使用异步解码，保留封面懒加载和预览前 4 张优先加载的规则；封面列表使用静态占位，避免大量持续动画，详情封面和预览图片使用旋转加载图标。完成后淡入，失败显示占位，章节预览图片可手动重试；重试不影响服务端图片缓存标识。所有动画继续遵守 `prefers-reduced-motion`。

## 漫画源操作反馈

`useSources` 用 `sourceOperation` 描述安装、更新、启用、禁用、刷新仓库和重载的操作类型、目标及状态文案。源列表、开关和安装按钮据此展示进行中状态，源变更期间防止重复操作。

源变更成功后仅刷新源数据并同步聚合搜索可选源，不附带刷新下载列表和缓存统计。全局刷新仍会并行刷新源、下载与缓存。首次源加载若本地仓库索引为空，会请求仓库并重新检查已安装版本；仓库失败时保留已取得的源列表。

## 下载操作与实时恢复

`useDownloads` 使用 `taskOperations` 和任务 ID 集合管理互斥：同一任务一次只接受一个操作，不同任务可以独立操作。缓存清理单独管理忙碌状态，不锁定所有下载任务。

高频任务快照存放在该 hook 创建并保持稳定的 `snapshotStore` 中，不通过 Workspace 的 React state 更新。`LiveDownloadsView` 使用 `useSyncExternalStore` 读取完整快照，只有下载页挂载时才订阅列表；`AppShell` 订阅活动任务数，该数值不变时无需随每次进度更新。切换页面时读取存储中的最新快照，不重新依赖某次父组件渲染携带的数据。搜索、源管理及详情弹窗不会因下载进度或活动任务数变化而重新渲染；用户操作、全局错误和连接提示等低频状态仍由现有 hook/Workspace 协调。

快照存储由每个 Workspace 单独创建，不是模块级单例；退出后随 Workspace 卸载，不在会话间共享下载列表。任务列表数组在下次快照写入前保持同一引用，供 React 稳定读取；活动任务数在写入时计算一次。HTTP 请求版本校验和 SSE 的到达顺序处理仍在 `useDownloads` 中完成，之后才写入存储。

- 排队中和运行中的任务提供暂停、取消；已暂停任务提供继续，失败任务提供重试下载。继续/重试下载使用服务端 resume 接口，保留已下载图片的恢复语义；取消后的重新下载使用 rerun 接口。
- 下载明细按需加载，加载错误保留在对应卡片并提供重新加载入口。没有记录与只看失败项时没有匹配记录分别显示空状态。`DownloadItemsList` 每页渲染最多 100 条，支持上一页、下一页和直接选择页码，重试操作始终传递当前行对应的原始图片记录。
- 排队和运行中的任务不能单图重试，需先暂停；停止执行的任务可逐图重试或调用服务端批量失败重试接口。
- 任务按状态分组，暂停任务单列；取消时保存的错误字段不应使已取消任务归入失败组，也不能使任务同时出现在多个组。
- 缓存操作仅清理临时图片缓存；删除任务与删除任务及文件是独立操作，后两者保留明确确认。
- 下载到本机先通过 POST CBZ 接口准备文件；准备期间保留任务级加载动画，失败不发起下载。成功后以同源原生下载获取文件，避免在前端内存中缓冲整个漫画；提示“已请求浏览器开始下载”不表示文件已保存完成。准备与实际 GET 会复用未失效归档，见服务端归档说明。

任务卡片在客户端按状态优先顺序排列后，每页渲染最多 50 个；过滤先于分页，汇总仍覆盖全部任务，本页分组计数明确标注为本页数量。切换任务页保留当前 Workspace 内的展开状态和已加载明细页，手动重新展开会刷新当前明细页；任务列表缩小时显示页限制在有效范围。任务列表接口和 SSE 仍返回完整任务数据，本轮只减少任务卡片 DOM 与渲染量。

图片明细改用服务端分页接口 `/downloads/{taskId}/items/page`，每次请求 100 条，并向服务端传递 `failedOnly`。hook 每个任务只保存当前一页及总数，分页控件根据服务端 total/offset/limit 请求新页，不再下载全量图片记录后切片。只看失败项由服务端先筛选再分页；切换筛选时清除旧页，已展开卡片按需重载，旧筛选的在途响应不得覆盖新筛选。发生加载错误时保留重试入口，不自动循环重试。任务级操作期间禁用筛选切换；请求版本校验仍保护异步边界。

重试图片后刷新原明细页，若该页已不存在而仍有记录，最多补取一次新的末页；记录清空时显示空状态。批量重试入口根据该任务的 `failedTotal` 判断，与当前页是否含失败图片无关，批量命令仍处理全部失败记录。批量响应类型引用 OpenAPI 生成的结构，最终任务只在外层 task 返回；结果行直接为 imageKey/ok/item 或 imageKey/ok/error，不保留旧格式分支。网页明细使用分页接口。

全本下载在最后一章解析前将 `totalKnown` 设为 false，卡片显示“已完成 / 已发现页数，总页数待确认”并使用不定进度条；已发现页数不当作最终分母。总数确认后恢复百分比；旧任务未带该字段时保持既有显示。

下载列表通过请求版本号协调 HTTP 与 SSE 快照。实时事件到达后，先前发出的列表请求返回时必须丢弃，避免进度或终态回退；较旧的 HTTP 请求也不能覆盖较新的请求。

服务端将纯进度通知按 100ms 窗口合并，窗口内只发送最新的完整任务快照；创建、删除、暂停、取消、失败、完成等状态变化仍即时推送。客户端不依赖每张图片对应一次事件，也不以收到的事件次数计算下载数量，直接显示快照中的 `completed/total`。

连接写缓冲满时，服务端只保留最新待发快照，恢复可写后发送；慢连接可能跳过中间进度或状态。前端以每次收到的完整快照替换列表，不要求逐条接收所有状态转换。该处理限制慢连接积压，不改变 EventSource 的重连及重新鉴权流程。

EventSource 错误时显示“正在自动重连，当前进度可能不是最新”，同时检查会话；连接重新打开后撤销提示，服务端订阅会发送当前完整任务快照。不要把断线直接等同于登录失效，认证失效仍通过 401 或 auth-expired 处理。

## 尚未实现的性能优化

以下为后续评估项，不属于当前能力：

- 图片缓存已增量维护；首次索引构建和显式统计仍扫描目录，元数据查询最多并发 8 个，大缓存需继续在 NAS 上验证冷启动成本。
- 下载纯进度广播已按 100ms 窗口合并，SSE 序列化结果按广播共享，前端已隔离下载快照订阅；事件仍携带完整任务列表，任务很多时需继续评估增量传输、JSON 解析和下载页本身的更新开销。
- 章节每页 100 章、任务卡片每页 50 个、图片明细由服务端每页返回 100 条；完整任务列表及 SSE 的传输、解析和内存仍随历史任务量增长。

## 功能边界

- 源设置和 Cookie 导入归属当前选择的源，避免与可安装源列表混用。
- 下载明细按需加载；批量失败重试调用服务端批量接口。
- 会导致数据丢失或客户端断连的操作应清晰提示后果，例如删除文件和撤销 Token。
- 功能围绕搜索、聚合搜索、下载和 NAS/VPS 部署需求；章节预览不保存阅读历史或恢复阅读进度。

## 2026-10-29 性能抽样

在生产构建上通过 Chrome DevTools Protocol 采集 `devtools.timeline` 时间线、主线程任务和长任务，启用 CPU 4 倍降速。使用独立模拟 API：快速源 150ms、慢速源 1500ms，详情 2000 章，下载列表 150 个任务并在 1 秒内发送 20 次快照。前后使用同样样本，未修改线上任务或源配置。

首轮前后对比：聚合首结果约 1859ms → 239ms；详情主线程任务总耗时约 285ms → 89ms，章节 DOM 数量 2000 → 100，详情长任务从一次约 130ms 降为本次未检出。下载更新开销前后接近，没有据此宣称优化效果。时间线反映该环境下的受控样本，不是线上真实用户 INP 或性能保证。

真实部署只读抽查：页面启动和源管理切换未发现未捕获页面异常；这不代替移动设备、满载下载和不同外部漫画源的持续验证。
