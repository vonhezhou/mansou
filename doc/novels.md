# 小说搜索与 TXT 下载（实验功能）

小说能力与漫画功能运行在同一个服务中，共用管理员鉴权、API Token、代理与数据目录。当前支持阅读书源的部分文本规则，不承诺导入任意书源即可使用，不提供阅读器。

## 使用

1. 打开侧栏“小说”，进入“书源与订阅”。
2. 上传或粘贴书源 JSON，可以是单个对象或对象数组；也可以添加直接返回这些 JSON 的 HTTP/HTTPS 合集订阅。
3. 查看搜索和下载能力提示，启用需要的源。支持仅表示规则在当前实现范围内，站点是否可访问仍需实际搜索验证。
4. 在“搜索”中输入书名或作者。勾选一个源为单源搜索，勾选多个源为聚合搜索；未勾选时搜索全部可用源。
5. 打开结果的“目录与下载”，核对目录顺序，下载全部目录或指定范围。起始位置以目录项计数，包含公告等原始条目。
6. 在“小说下载”中暂停、继续、取消、重试或删除任务。全部选定章节成功后，点击“下载 TXT”保存到浏览器所在设备。

项目不内置或自动安装第三方书源。每次导入最多 2000 条、请求体最多 8 MiB；每次搜索最多 100 个源，并发搜索 3 个。来源、作者缺失时不只凭同名合并不同作品。

## 自定义与订阅

相同地址的自定义书源再次保存时替换规则。可以从已导入源加载原始 JSON 编辑；订阅源编辑后保存为独立的自定义源，保留订阅原版本，两者互不覆盖。

订阅当前由用户手动刷新。刷新成功时以新合集替换该订阅的源，保留相同地址的启停设置，新增源遵循原始 enabled 字段，移除合集已删除的源。刷新失败保留原规则并记录错误。不同订阅中的相同书源按订阅身份区分，不自动覆盖或合并。

停用订阅会使其源退出搜索；移除订阅同时移除所属源，均不影响已创建任务的规则快照。仅删除某个订阅源后，下次刷新可能重新出现。

类似书源管理页抓取规则的“订阅”不是书源 JSON 合集，当前不支持。网页不会自动执行 JSON 中的 JS。

## 支持范围与限制

- 支持 HTML/CSS、常用 Jsoup 风格链式选择、索引、常用正则替换、GET/POST、静态 JSON/JSON5 请求选项及 GBK 等编码。
- 搜索使用 ruleSearch；目录使用 ruleBookInfo.init/tocUrl、ruleToc；正文使用 ruleContent，支持目录及正文分页、URL 去重和明确的逆序目录标记。
- 暂不支持 JS、Java 宿主、XPath、JSONPath、浏览器验证、登录或 Cookie 会话语义。未实现的规则明确失败，不静默当作成功。
- 搜索成功不代表详情或下载成功；目录遍历完成不代表作品完结、站点无缺章、正文无广告。不会猜测并删除公告，也不会按章名任意重排。
- 目录规则匹配到的有效条目必须同时有标题和链接，缺少任一项即失败，不能静默跳过后标为完整。仅无文字、无链接、无子元素的纯空白占位可以跳过，例如表格补列的空单元格。包含卷名等无链接条目的页面应调整 chapterList，只匹配实际章节；isVolume 等卷信息规则暂不支持。
- 默认最多遍历 100 页目录、每章 20 页正文；目录最多 50000 项，单页响应最多 2 MiB，单章正文最多 4 MiB，TXT 正文合计最多 200 MiB。超过限制明确失败。
- HTML 和正则解析在可终止 Worker 中执行，最多同时 4 个线程，每个线程限制 128 MiB 老生代。搜索操作总时限为请求超时加 2 秒启动余量，目录或单章操作总时限为 120 秒。这不代表进程总内存上限。

## 持久化与恢复

源、订阅、下载任务和下载计划保存在同一个 mansou.sqlite 的 novel_records 表中。创建任务即固定原始规则；成功解析目录后固定目录及下载范围，恢复时不因订阅更新重排章节。

文件保存在数据目录的 downloads/novels/<任务 ID>/ 下：数字命名的 TXT 是完整章节缓存，book.txt 是最终导出。章节及最终导出先写临时文件再重命名；失败或暂停不对外提供成功 TXT。恢复时核查已完成章节文件是否存在并跳过，丢失的章节重新抓取。恢复粒度为章节，中断的章节会重新下载。

服务重启会重新排队原先排队或运行的任务，保留用户暂停、失败及取消状态。失败任务需点击重试。删除任务同时删除其文件与计划。备份和恢复时应保留 SQLite 及 downloads/novels 文件，不能只备份导出的 book.txt。

加载目录时可以关闭目录、切换小说功能页面或离开小说入口；网页会取消请求，服务端连接断开后终止对应 Worker 和上游请求。超时、HTTP 错误、响应过大和规则不支持的错误码会跨线程保留。

小说下载复用 MANSOU_DOWNLOAD_TASK_CONCURRENCY、MANSOU_DOWNLOAD_RETRIES、MANSOU_REQUEST_TIMEOUT_MS 和代理配置，具体变量以[配置参考](configuration.md)为准。漫画和小说分别使用任务调度器，因此任务并发上限分别计算；小说状态仅在小说页面打开时轮询，不计入漫画下载页与侧栏下载数量。

## 开发接口

契约源为 packages/contracts/openapi.yaml，运行时通过 /api/v1/openapi.json 查看。小说接口统一位于 /api/v1/novels 下，包括 sources/import、subscriptions、search、catalog、downloads 及 downloads/{id}/txt。网页类型从同一 YAML 生成，写操作沿用现有 CSRF 防护。

packages/novel-engine 来自项目作者的独立预研实现，本仓库按 MIT 提供；Legado 是第三方 GPL-3.0 项目，作为格式与行为参考。第三方书源不随本项目重新许可，见[第三方说明](../THIRD_PARTY_NOTICES.md)。

## 本轮验证记录

2026-10-31，首版在开发机通过构建、类型检查及全仓库 380 项测试；浏览器使用可控站点夹具验证 JSON 导入、搜索、目录、下载和 TXT 内容，并检查 1440px 桌面及 390px 移动端。

另对就爱文学、新笔趣阁两个原始基线源低频搜索“凡人”：分别返回 50、30 条结果，解析到 552、2467 项目录，并分别成功下载前两项到 TXT。这是样章验证，不是整本、持续可用性或 NAS 性能验收。未修改、打包或内置这些第三方源，未在目标 NAS 上部署。

后续可靠性修复增加了目录缺项、纯空白补列、Worker 错误码、真实 HTTP 断开和网页取消回归，全仓库 391 项测试通过。继续使用就爱文学的原始规则，对《凡人渺渺》遍历到的完整 5 章目录执行全部下载，首项“第一章 打铁父子”、末项“第五章 黑山（二）”，TXT 为 44637 字节；这次短目录验证同样不代表长篇整本已验收。
