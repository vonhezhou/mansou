# Lessons

- 当用户在多仓库父目录中提到具体模块（例如 `server`）时，必须先确认目标子项目路径；本项目的 server 位于 `venera_web/apps/server`，不要默认使用旁边的 `venera` 仓库。
- 当用户明确产品目标（例如“搜索、聚合搜索和下载”）后，后续迭代必须围绕该目标收敛；不要主动扩展到阅读器、阅读进度、历史恢复等未确认方向。若阶段计划中出现偏离目标的功能，必须先向用户确认。
- 当用户明确部署目标是 NAS/VPS 时，优先级必须转向可部署性、数据持久化、访问控制、安全边界、Docker/Compose、反向代理、日志、备份恢复和资源占用；不要优先做桌面端/PWA/多用户等非部署闭环能力。
- `venera_web/apps/web` 当前未上线时，UI 大重构应以通过回归为边界直接做根本性结构调整，不要为了当前 PoC 结构做临时折中或兼容层；章节图片展示定位为章节预览，不是阅读器。
- 为根 `dev` 脚本组合启动多个长期运行服务时，不要依赖 `pnpm --parallel --filter ... dev` 这种容易被用户环境/输出顺序误判的写法；应显式用 `pnpm dev:server & sleep 1; pnpm dev:web & wait` 之类脚本表达启动顺序，并保留单独 `dev:server`/`dev:web`。
- 源管理 UI 中不要把“当前操作源”和“可安装源”并排混放；源设置、Cookie 导入等针对单个源的操作必须归入独立的“当前操作源”功能块，避免用户误解为全局或仓库级操作。

- 用户要求以 OpenAPI YAML 定义交互协议时，采用契约优先：YAML 是唯一源文件，类型和运行时文档由其生成，不要反向从手写 TypeScript 文档导出 YAML。
