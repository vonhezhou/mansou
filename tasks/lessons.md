# Lessons

- 千条级源管理必须提供分页和按筛选范围批量操作，明确区分本页与全部筛选结果，变更筛选时清空选择；批量失败保留选择，删除须确认数量。复选框标签使用显式同行布局，避免继承通用表单网格造成错位。不支持下载的规则必须在写入前拒绝，并显示成功/拒绝数量及原因；不能把静默丢弃或保留历史记录描述为用户已看到拒绝结果。

- 小说搜索按用户最新取舍固定聚合全部已启用且支持搜索、下载的源，不再提供单源模式或选源控件；漫画搜索保持原交互。失败源仅进入折叠提示，不占结果分组。自定义导入和订阅更新均过滤不支持下载的规则；网络暂时失败不等同于规则不支持，不据此删除源。此约定覆盖此前小说复用漫画单源及选源模式的要求。

- 当前项目唯一客户端是同仓库网页。调整接口时同步修改服务端、OpenAPI 和网页调用，不为假设中的旧客户端保留兼容分支或增加可选兼容模式；若客户端范围发生变化，再重新确认契约约束。

- 当用户在多仓库父目录中提到具体模块（例如 `server`）时，必须先确认目标子项目路径；本项目的 server 位于 `venera_web/apps/server`，不要默认使用旁边的 `venera` 仓库。
- 当用户明确产品目标（例如“搜索、聚合搜索和下载”）后，后续迭代必须围绕该目标收敛；不要主动扩展到阅读器、阅读进度、历史恢复等未确认方向。若阶段计划中出现偏离目标的功能，必须先向用户确认。
- 当用户明确部署目标是 NAS/VPS 时，优先级必须转向可部署性、数据持久化、访问控制、安全边界、Docker/Compose、反向代理、日志、备份恢复和资源占用；不要优先做桌面端/PWA/多用户等非部署闭环能力。
- `venera_web/apps/web` 当前未上线时，UI 大重构应以通过回归为边界直接做根本性结构调整，不要为了当前 PoC 结构做临时折中或兼容层；章节图片展示定位为章节预览，不是阅读器。
- 为根 `dev` 脚本组合启动多个长期运行服务时，不要依赖 `pnpm --parallel --filter ... dev` 这种容易被用户环境/输出顺序误判的写法；应显式用 `pnpm dev:server & sleep 1; pnpm dev:web & wait` 之类脚本表达启动顺序，并保留单独 `dev:server`/`dev:web`。
- 源管理 UI 中不要把“当前操作源”和“可安装源”并排混放；源设置、Cookie 导入等针对单个源的操作必须归入独立的“当前操作源”功能块，避免用户误解为全局或仓库级操作。

- 用户要求以 OpenAPI YAML 定义交互协议时，采用契约优先：YAML 是唯一源文件，类型和运行时文档由其生成，不要反向从手写 TypeScript 文档导出 YAML。

- 评估 server 代码结构时，必须同时检查路由、业务服务、插件运行时、存储与依赖方向；不能把整体代码结构优化收窄为插件架构选择。先展示实际结构，再区分当前实现与目标设计。

- 当前项目尚未上线，NUC 为可清理的测试环境；命名与结构调整应直接统一实现，不为未上线的旧配置、数据库或会话标识增加兼容层。未经明确部署指令，不操作 NUC。

- 多仓库集成时先区分代码归属与许可：`legado_book_source` 是用户独立编写、未发布的预研项目，`legado` 是第三方 GPL-3.0 项目；不能把两者混为同一授权来源，也不能仅因独立实现兼容运行时或加载 JSON 就断言整个宿主仓库适用 GPL。复制或实质改编第三方实现需单独核查。

- 部署的数据保留检查应比较持久化源元数据、启停状态及任务身份，并另核对真实启用源是否加载；不要把含临时测试源的运行时列表当作持久化数据。旧版注入但从未入库的 mock 不应为通过验收而重新注入。

- 搜索结果的目录入口必须在当前视口给出可见反馈，并支持直接点击书籍卡片；不能只在长列表底部插入目录后就把接口成功当成交互验收通过。真实浏览器验收同时检查目录位置、加载与失败提示，以及用户自然点击路径。

- 小说搜索等同类功能的 UI 优先参考并复用仓库已有的漫画搜索模式，包括搜索方式、源标签、结果卡片、错误摘要和详情弹窗；不要另造一套列表及目录展开方式。保留业务差异，并验证空选择、取消、焦点恢复和下载闭环。

- 按功能组织工作台入口：小说搜索只负责搜索和详情，书源与订阅应有与漫画源并列的独立管理入口；漫画和小说下载统一进入下载任务与侧栏活动计数。整合时保留各自任务 API 和数据身份，进度快照独立订阅，避免刷新搜索页或源管理表单。

- 新增与既有管理入口并列的导航时，同步核对数量徽标和图标语义。小说源数量按全部已导入记录统计，包含停用源；由工作台共享状态驱动并随导入、删除、订阅刷新更新。小说搜索、小说源和漫画源使用可区分的图标，桌面与移动端一起验收。
